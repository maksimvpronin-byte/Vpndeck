# Включение ограничений доступа

Изменения подготовлены локально. Этот порядок не выполняет развёртывание автоматически.

## Перед обновлением

1. Сохранить текущий бинарник vpndeck-server, server.json и конфиг Xray с исходными правами доступа. В этих файлах есть секреты; не добавлять копии в Git.
2. Зафиксировать список `vpndeck-server devices` и проверить, что у каждого действующего телефона есть отдельное устройство.
3. Обновить Android-клиенты до сборки с понятными сообщениями `device_required` и `device_registration_closed`. Формат успешного ответа сервера не менялся.
4. Проверить версию Xray на VPS. Локальная проверка маршрутизации прошла на Xray 26.10.21 из setup-xray.sh (linux/arm64, digest `sha256:d5c3729dfeed7c412af17a63b941c48c76ba68afee5b6184fe4078f8fa8bedcc`). Повторное скачивание образа прошло успешно.

## Порядок включения

1. Обновить сервер, пока новые флаги выключены. Проверить вход, получение профиля и подключение существующего телефона.
2. Включить `manage_devices`, если ещё не включён. Дождаться миграции телефонов на отдельные UUID.
3. Добавить `require_device: true` в существующий JSON-объект server.json. Проверить вход зарегистрированного телефона и отказ 401 `device_required` для входа без ID и общего профиля старого токена.
4. Удалить только общий клиент из выбранного inbound Xray, сохранив клиентов устройств. Проверить конфиг Xray перед перезапуском. Перезапуск прервёт текущие соединения.
5. Включить `disable_new_devices: true`. Проверить, что известный ID входит, а новый ID получает 401 `device_registration_closed`. Для подключения новых телефонов регистрацию временно открывают.
6. Перенести правило `geoip:private` и стратегию `IPOnDemand` из setup-xray.sh в существующий routing, сохранив остальные правила; блокировку разместить перед разрешающими правилами. Убедиться, что outbound `block` использует `blackhole`.
7. Проверить доступ к обычному внешнему сайту, отказ к внутреннему IP и домену, разрешающемуся во внутренний IP. Правило не заменяет сетевую изоляцию и само по себе не закрывает доступ к публичному адресу хоста.
8. Отозвать специально созданное тестовое устройство: его токен, повторный вход с тем же ID и VPN UUID должны перестать работать. Убедиться, что смена ID при закрытой регистрации не помогает.

## Откат

При проблемах совместимости сначала выключить новые флаги. Это не восстанавливает удалённый общий UUID: его возвращают отдельно из резервной копии только при осознанной необходимости старых клиентов. При откате конфига Xray сохранить актуальные отзывы устройств, чтобы не вернуть доступ ранее отозванным UUID. После любого изменения Xray проверить конфиг и перезапустить выбранный контейнер.

## Выполненные локальные проверки

- Go: все тесты с детектором гонок и go vet прошли.
- Android: 30 unit-тестов прошли; lintRelease прошёл с 11 предупреждениями.
- Android: добавлено распознавание новых причин отказа; пароль исключён из сохраняемого состояния экрана.
- Токен и профиль хранятся в приватных SharedPreferences без дополнительного шифрования. Backup и перенос этих настроек запрещены конфигурацией приложения.
- В коде запросов API проверяется закреплённый SPKI; HTTP-перенаправления запрещены. Первое доверие ключу требует подтверждения пользователя. Автоматическая ротация закреплённого ключа не реализована.
- Установщик проверяет пакет, увеличение версии и совпадение подписантов APK. CI запускает серверные и Android-тесты, lint и проверку APK; публикация релиза остаётся отдельным действием.
- На локальном Xray 26.10.21 проверено: тестовый HTTP-сервис доступен без правила; после включения правила закрыт доступ по приватному IP и домену с приватным DNS-ответом. Тестовые контейнеры и сеть удалены.
- Сквозная проверка с телефоном и установленной версией Xray на VPS ещё необходима. CI был проверен по конфигурации, новый запуск GitHub Actions не выполнялся.
